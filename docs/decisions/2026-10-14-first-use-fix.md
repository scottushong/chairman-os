# 2026-10-14 운영 첫 사용 고침 — 스스로 정한 것 (묻지 않음 · 한 줄씩)

- 400 원인 확인은 운영 로그 대신 로컬 재현(같은 스키마 · 가짜 시트 · 진짜 호출 1번) — 오류 문장이 그대로 나와(«additionalProperties: object is not supported») Vercel 로그를 열 필요가 없었다.
- 칸 대응은 `[{field, col}]` 배열로(이름 → 열 object를 없앰). 다른 길(스키마 강제를 끄고 글로 받기)은 형식 보장이 사라져 버림.
- 같은 실수가 다른 AI 경로에 숨지 않게 `check:ai-schemas`(구조 강제 스키마 8개) — check:finance-upload도 부른다. 어시스턴트 도구 스키마(strict 아님)는 규칙 밖이라 넣지 않음.
- 브리핑 · 첨부 요약 · 입구는 400이면 강제 없이 한 번 물러서는 길이 이미 있다 — 그대로 두고 스키마만 검사.
- 원장 2배의 정확한 원인 줄은 진짜 파일을 볼 수 없어(금지) «괄호 · 띄어쓰기가 붙은 요약 줄 + 날짜 칸이 찬 일계 줄»로 추정 — 검사에서 그 모양으로 2배를 재현하고 새 규칙으로 사라짐을 확인. 실제 파일은 배포 뒤 «다시 해석»으로 확인.
- 요약 줄 규칙은 «핵심 글»(띄어쓰기 · 괄호 · 별표 · 쌍점 걷음)이 낱말과 **같을 때**만 — «합계상사» 같은 거래처 이름은 거래로 남긴다(포함 검사는 거래를 지울 위험).
- 날짜 칸이 있고 금액 줄 60% 이상에 날짜가 있으면, 날짜 없는 금액 줄은 «모르는 줄»로 더하지 않고 검증 오류로 보인다(조용히 더하지도 버리지도 않음).
- 대조 기준: 계정마다 월계(여러 개면 합) → 없으면 합계. 누계는 앞 달이 섞일 수 있어 기준으로 쓰지 않는다.
- 잔액 흐름으로 칸 고치기는 «지금 대응이 반도 안 맞고(또는 셀 수 없고) 다른 대응이 90% 이상 맞을 때»만 — 우연히 바꾸지 않게.
- 원장은 요약 줄과 대조가 된 해석만 «믿음 높음»(코드만으로 맞으면 AI 0번). 대조할 줄이 없으면 AI에 한 번 보이고, 경고(«대조하지 못했습니다»)가 남아 자동 넣기는 안 된다.
- 재해석 때 AI에 주는 차이에는 **금액을 싣지 않는다**(«정확히 2배» · «부호 반대» · 거래로 더한 줄 번호만) — 0080 원료 금액 가림과 같은 원칙(원재료 계정 금액이 원료 숫자다).
- 재해석 천장 = 시트당 3번(처음 1 + 다시 2). 파일 한도 env가 더 작으면 그것 — 운영 env `FINANCE_UPLOAD_AI_PER_FILE`은 3 권장(반영 문서 0).
- 학습 표는 마이그레이션 없이 0070 `fin_upload_shape_save` 규칙(키 40자 · 값 0~200 정수) 안에 담는다: `@date` 같은 원장 칸 · `#<줄 종류>:<낱말>` = 1. 숫자(금액)는 담지 않는다 — staging 시험으로 받아들임 확인. 0072 넷(평가 · 출고 · 세금계산서 · 원장 거래 줄)은 학습 표 종류 제약 밖이라 저장하지 않음.
- 학습 모양으로 읽었는데 대조가 틀리면 학습을 믿지 않고 다시 해석한다(양식이 바뀐 달). «다시 해석»은 학습 모양을 쓰지 않고(틀렸을 수 있음) 성공하면 덮어쓴다.
