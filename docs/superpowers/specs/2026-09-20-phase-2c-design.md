# Phase 2-C — 공식 재무제표 입력 + 월별 간이 손익

2026-09-20. 상태: 설계.

원칙은 그대로다. **회계 원천은 장부다(0015/0016).** 이 두 화면은 장부에 쓰는 '편한 입구'지
장부를 대신하는 곳이 아니다. 출처·마감·정정·audit_log 규칙을 하나도 비켜 가지 않는다.

---

## 0. 지시와 다르게 가는 것 하나 — 공식 재무제표는 `closings`에 넣지 않는다

지시는 "저장 → `closings`에 `source='official'`, `closed=true`"였다. **그대로 하면 숫자가 깨진다.**

`closings`는 스키마 주석이 못 박은 대로 **월 단위**다:

> `amount` = 차변 − 대변. 손익 계정은 **그 달 발생액**, 상태표 계정은 월말 잔액.
> `period text not null check (period ~ '^[0-9]{4}-[0-9]{2}$')`

공식 재무제표는 연간 또는 분기다. 2025년 결산 매출 700억을 `closings`의 `2025-12` 칸에
넣으면 그 달 발생액이 700억이 된다. 그 값은 `finance_ledger_cells` → `finance_kpis` 뷰를
그대로 타고 올라가 **12월 한 달 매출이 700억인 추이 차트**를 그린다. 연간 총액과 월별 합이
같은 표에서 더해지면 YTD도 두 배가 된다.

**그래서 공식 재무제표는 자기 표를 갖는다.** 층이 둘이 되고, 둘은 겹치지 않는다:

| 층 | 무엇 | 기간 | 표 | 꼬리표 |
|---|---|---|---|---|
| 공식 | 회계법인 결산 | 연 또는 분기 | `official_statements` + `_lines` | 확정 |
| 월별 | 회장·재무 담당이 넣는 간이 손익 | 월 | `journal_entries` + `journal_lines` | 잠정 |

겹치지 않는 이유는 블록 2가 **공식이 덮은 기간의 셀을 잠그기** 때문이다. 2025년에 공식
결산이 있으면 2025년 월별 칸은 잠긴다. 그래서 "기준: 2025 결산(확정) + 2026 1~8월(잠정)"이
그대로 사실이 된다 — 그 문장이 이 설계의 요약이다.

`source='official'`은 **필요가 없어진다.** 공식 재무제표가 자기 표에 있으면 *그 표에 있다는
사실 자체가 출처*다. `data_source` enum에 값을 더하면 얻는 것 없이 함정만 생긴다 —
`alter type ... add value`로 넣은 값은 **같은 트랜잭션 안에서 쓸 수 없어서**
(마이그레이션 한 파일 = 한 트랜잭션) enum 추가와 사용을 두 마이그레이션으로 갈라야 한다.

"회계법인이 준 숫자"와 "회장이 손으로 넣은 숫자"의 구분은 표 + 증빙 링크 + 메모가 한다.

대안과 안 고른 이유는 DEFERRED D-23에 남긴다.

## 1. 스키마 — 0020

### 1-1. enum은 건드리지 않는다

`data_source`도 `FIGURE_BASIS`도 그대로 둔다. 공식 재무제표의 꼬리표는 코드에서
**확정(confirmed)** 으로 정한다 — 그 표에 들어왔다는 것이 곧 마감된 결산이라는 뜻이다.
화면에 '공식'이라는 새 꼬리표를 만들지 않는 이유는, 회장이 알아야 하는 것은
"이 숫자가 움직이느냐(확정/잠정)"이지 누가 만들었느냐가 아니기 때문이다.
누가 만들었는지는 증빙 링크와 메모가 말한다.

### 1-2. `official_statements` — 헤더

```
business_id   text     -- businesses FK
period_kind   text     -- 'year' | 'quarter'
period_key    text     -- 'YYYY' | 'YYYY-Q1'..'YYYY-Q4'
evidence_url  text     -- 필수. https만. 파일 실체는 사내 스토리지(CLAUDE.md)
memo          text     -- 필수. '성연회계법인 2025 결산'
created_by    uuid
created_at    timestamptz
supersedes_id bigint   -- 같은 기간 재입력이면 이전 것을 가리킨다
```

- PK는 `id`. **활성 행 유일성**은 부분 유니크 인덱스로 건다:
  `unique (business_id, period_kind, period_key) where superseded_at is null`.
- 재입력은 **정정**이다. 이전 행에 `superseded_at`을 찍고 새 행이 그것을 가리킨다.
  전표를 고치지 않는 0016의 규칙과 같은 모양이다 — **덮어쓰지 않고 쌓는다.**
- 이전 값 전체를 `audit_log`에 남긴다.

### 1-3. `official_statement_lines` — 항목

```
statement_id  bigint   -- official_statements FK, on delete cascade
account_code  text     -- (business_id, account_code) → accounts FK
amount        numeric(20,2)
```

계정은 **0016 표준표(`STANDARD_CHART`)의 대분류별 30~40줄**을 기본으로 깔고,
회사별 추가 계정은 `accounts`에 이미 있는 것을 고른다(새 계정과목 체계를 여기서 만들지 않는다).

### 1-4. RLS

읽기는 `has_business(business_id) and can_read_restricted()` — `closings`와 같은 문.
쓰기는 `can_keep_books(business_id)`. AI Agent·Integration은 **쓰기 금지**(restrictive policy),
0016의 `journal_entries`와 같다. update/delete 정책은 두지 않는다 — 정정으로만 바꾼다.

## 2. 블록 1 — `/finance/[business_id]/statements/new`

### 화면

- 기간 선택: 연도 또는 분기.
- 탭 둘: **재무상태표**, **손익계산서**.
- 항목: 표준표 대분류별 30~40줄. 대분류 소계는 **입력이 아니라 계산된 줄**이다.

### 검증 — 안 맞으면 저장 버튼이 안 눌린다

1. **자산 = 부채 + 자본.** 차이를 원 단위로 띄운다. "1,200원 안 맞습니다"처럼 금액을 적는다 —
   '검증 실패'만 뜨면 어디를 볼지 알 수 없다.
2. 손익 소계(매출총이익·영업이익·당기순이익)는 자동 계산이고 수정 불가.
3. 증빙 URL과 메모가 비면 저장 불가.

**왜 막는가.** 안 맞는 재무상태표를 확정으로 저장하면 그 뒤의 모든 화면이 틀린 값을
확정 꼬리표로 보여 준다. 잠정은 틀려도 고쳐지지만 확정은 신뢰의 근거다.

### 저장

1. 같은 기간에 활성 행이 있으면 **덮어쓰기 확인**을 먼저 받는다. 무엇이 바뀌는지
   (기존 총액 → 새 총액) 보여 준 뒤에 묻는다.
2. 이전 행 `superseded_at` 찍기 → 새 헤더 + 라인 삽입 → `audit_log`.
   이 셋은 한 트랜잭션이다. 나뉘면 '활성 행이 둘'이거나 '하나도 없는' 순간이 생긴다.

## 3. 블록 2 — `/finance/[business_id]/monthly`

### 화면

12개월 × 항목의 표. 셀을 누르면 그 자리에서 입력한다.

기본 항목(회사 유형별로 다르다):

| 유형 | 항목 |
|---|---|
| 제조(DY 형) | 매출 / 매출원가 / 인건비 / 임차·관리 / 마케팅 / 외주·용역 / 기타비용 / 영업외손익 / 현금잔액 / 매출채권 / 매입채무 |
| 스타트업(간이형) | 위에서 매출원가·외주를 빼고 시작 |

항목 추가·숨김이 된다. 숨김은 **그 회사의 화면 설정**이지 계정 삭제가 아니다.

### 붙여넣기

엑셀에서 열 하나(12칸)를 복사해 한 항목 줄에 붙이면 12개월이 채워진다.
탭·줄바꿈 둘 다 구분자로 받고, 통화 기호·천 단위 쉼표·괄호 음수 `(1,200)`를 해석한다.
**해석 못 한 칸은 비워 두고 몇 칸이 실패했는지 말한다** — 조용히 0을 넣으면 그 0이 장부에 간다.

### 저장 → 요약 전표 자동 생성

셀 하나가 전표 한 줄이 아니다. **한 달치를 한 전표로 묶는다**:

- `journal_entries` 한 행: `slip_no = M{YYMM}-S{nn}`, `memo = '{YYYY-MM} 월별 간이 손익'`
- `journal_lines`: 항목별 한 줄씩, `source='manual'`, `closed=false` → **잠정**
- 차·대가 안 맞으면 차액은 **미분류 계정**으로 떨군다. 숨기지 않고 화면에도 그 줄을 보여 준다.

마감은 **기존 월 마감 버튼**을 그대로 쓴다. 이 화면은 마감하지 않는다.

### 잠금

공식 재무제표가 덮은 기간의 셀은 입력 불가 + **'확정'** 표시. hover로 근거
("2025 결산 · 성연회계법인")를 보여 준다.

## 4. 블록 3 — 연결

1. `finance_kpis` 뷰는 **손대지 않는다.** 월별 간이 손익이 `journal_lines`에 들어가므로
   기존 경로로 그냥 읽힌다. 이것이 '장부에 쓰는 입구'로 설계한 이유다.
2. 공식 재무제표는 뷰 밖이다. 연·분기 총액이 필요한 자리(회사 상세 헤더, YTD)에서
   `official_statements`를 따로 읽어 **더 강한 층으로 덮는다.**
3. 회사 상세 상단 한 줄: `기준: 2025 결산(확정) + 2026 1~8월(잠정)`.
   문장은 두 층을 실제로 조회해 만든다 — 하드코딩하면 첫날부터 거짓말이 된다.

## 5. 검증

`scripts/check-statements.ts` (`npm run check:statements`), 오프라인·DB 없음:

1. 재무상태표 균형 검사가 1원 차이도 잡는다.
2. 손익 소계 계산이 표준표 대분류와 일치한다.
3. 붙여넣기 파서: 탭/줄바꿈, 쉼표, 통화 기호, 괄호 음수, 빈 칸, 12칸 초과·미만.
4. 요약 전표 생성이 차·대 균형을 지키고, 안 맞으면 미분류로 떨군 금액이 차액과 같다.
5. 공식 기간과 월별 기간이 겹칠 때 잠금 판정.

수동(dummy): VANA에 2025 결산 입력 → 2026 1~8월 월별 입력 → 8월 마감 →
차트·3표·KPI가 같은 값을 말하는지 → 스크린샷 → staging.
