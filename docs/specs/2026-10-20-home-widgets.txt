현재 개발 중인 사내 그룹웨어에 직원별로 위젯을 구성할 수 있는 개인 홈 화면을 구현해줘.

먼저 기존 프로젝트의 기술 스택, 로그인·권한 체계, 화면 구성, API와 데이터베이스를 확인하고 그 구조에 맞춰 작업해줘. 기존에 구현된 결재·업무·일정 등의 기능을 최대한 재사용하고, 홈 화면에서 해당 기능으로 연결되도록 해줘.

1. 화면의 목적

직원이 로그인하면 다음 내용을 한눈에 파악할 수 있어야 한다.

- 지금 내가 처리해야 할 일
- 내가 결재해야 할 문서
- 내가 요청한 업무의 진행 상황
- 오늘과 이번 주 일정
- 놓치면 안 되는 회사 공지

직원마다 필요한 정보가 다르므로, 위젯의 종류·순서·크기·표시 범위를 개인별로 설정할 수 있어야 한다.

2. 전체 화면 구성

상단:
- 회사 로고와 기존 공통 메뉴
- 로그인한 직원의 이름과 부서

좌측:
- 내 홈
- 전자결재
- 업무관리
- 일정
- 공지사항
- 문서·자료실
- 근태·휴가
- 조직도

본문 상단:
- 날짜와 사용자 이름
- ‘홈 편집’ 버튼
- 회사가 지정한 필수 공지 영역

본문:
- 개인이 구성한 위젯 영역

필수 공지 영역은 개인이 삭제하거나 숨길 수 없도록 한다. 관리자에게 지정 권한을 주고, 사용자가 열람할 수 있는 공지만 표시한다. 나머지 일반 공지는 선택형 위젯으로 제공한다.

3. 최초 기본 배치

개인 설정이 없는 직원에게는 다음 배치를 제공한다.

첫째 줄:
- 내 업무: 넓게
- 전자결재: 작게

둘째 줄:
- 일정: 작게
- 요청한 업무: 작게
- 근태·휴가: 작게

셋째 줄:
- 즐겨찾기: 작게

이후에는 직원이 저장한 개인 배치를 우선 적용한다.

4. 위젯 종류와 표시 내용

① 내 업무
- 업무 제목
- 진행 상태
- 마감일
- 요청자 또는 관련 부서
- 기한 지남·오늘 마감 표시
- 진행 중 / 이번 주 마감 등의 표시 범위 선택
- 기본 정렬은 기한 지난 업무, 마감 임박 업무 순서

② 전자결재
- 문서 제목
- 기안자
- 상신일
- 현재 결재 단계
- 내 결재 대기 / 내가 올린 문서 선택

③ 일정
- 시간
- 일정 제목
- 장소 또는 관련 부서
- 내 일정 / 부서 일정 선택

④ 요청한 업무
- 내가 요청한 업무 제목
- 담당자
- 현재 처리 상태
- 예정 완료일 또는 마감일

⑤ 근태·휴가
- 오늘 출근 기록과 근무 상태
- 내 잔여 연차
- 권한이 허용된 범위의 부서 부재자
- 휴가 신청 화면 연결

⑥ 즐겨찾기
- 자주 쓰는 결재 양식
- 그룹웨어 내부 메뉴
- 승인된 외부 업무 시스템 링크
- 직원별 항목 추가·삭제·순서 변경

⑦ 최근 문서
- 접근 가능한 최근 문서
- 문서명
- 수정일
- 담당자 또는 부서

⑧ 안전·설비 요청
- 내가 담당하거나 요청한 현장 업무
- 설비명 또는 위치
- 처리 상태
- 조치 기한

⑨ 부서 공지
- 내 부서 공지
- 게시일
- 필독 여부
- 읽음 여부

각 항목을 누르면 기존 상세 화면으로 이동하도록 한다. 위젯에서 전체 목록으로 이동할 수도 있어야 한다.

위젯의 목록과 요약 건수에는 동일한 조건을 적용한다.

5. 홈 편집 기능

평상시에는 업무 확인에 집중할 수 있도록 이동·삭제·크기 조절 도구를 숨긴다.

‘홈 편집’을 누르면 다음 기능을 표시한다.

- 위젯 추가
- 위젯 제거
- 드래그로 순서 이동
- 키보드와 모바일에서도 사용할 수 있는 앞·뒤 이동 버튼
- 크기 변경
- 배치 저장
- 취소

위젯 크기는 다음 세 가지로 제공한다.

- 작게: 데스크톱 가로 폭의 약 1/3
- 넓게: 약 2/3
- 전체 폭: 한 줄 전체

위젯 추가 목록에서는:
- 본인 권한으로 이용 가능한 위젯만 보여준다.
- 위젯 이름과 짧은 설명을 표시한다.
- 이미 추가된 위젯은 ‘추가됨’으로 표시한다.
- 초기 버전에서는 같은 위젯의 중복 추가를 막는다.
- 제거했던 위젯을 다시 추가할 수 있게 한다.

저장과 취소:
- 편집 중 변경은 임시 상태로 관리한다.
- 저장 성공 후에만 개인 배치에 반영한다.
- 취소하면 편집 직전의 배치·크기·표시 설정으로 복원한다.
- 저장 실패 시 편집 내용을 유지하고 재시도할 수 있게 한다.
- 저장하지 않은 상태에서 화면을 나가려 하면 변경 사항을 확인한다.

6. 개인 설정 저장

개인 배치는 로그인한 사용자 계정에 연결해 서버에 저장한다. 다른 PC에서 로그인하거나 새로고침해도 복원되어야 한다.

프로젝트 구조에 맞춰 다음 정보를 저장한다.

- 사용자 식별자
- 레이아웃 스키마 버전
- 설정 수정 버전 또는 수정 시각
- 위젯별 고유 식별자
- 위젯 종류
- 정렬 순서
- 크기
- 표시 범위와 필터
- 즐겨찾기 설정

데이터베이스 구조와 API는 기존 방식에 맞춰 구현한다. 서버는 로그인 세션에서 사용자 신원을 확인하고, 요청 본문의 사용자 식별자만 믿고 다른 직원의 설정을 수정하게 해서는 안 된다.

여러 탭에서 동시에 수정해도 최신 설정을 무심코 덮어쓰지 않도록 충돌을 처리한다.

신규 위젯이 생겼다는 이유로 기존 직원의 배치를 초기화하지 않는다. 삭제된 위젯 종류나 권한을 잃은 위젯이 포함되어 있어도 나머지 홈 화면은 정상적으로 표시한다.

7. 반응형 화면과 권한

데스크톱:
- 3열을 기준으로 구성한다.
- 기존 디자인 시스템이 있다면 그 규칙을 따른다.

태블릿:
- 2열로 전환한다.
- 넓은 위젯은 화면 범위에 맞춰 표시한다.

모바일:
- 1열로 구성한다.
- 데스크톱에서 저장한 순서를 유지한다.
- 드래그 없이도 이동 버튼으로 편집할 수 있게 한다.

화면을 채우기 위한 불필요한 큰 그래프나 빈 공간은 넣지 않는다. 제목·상태·담당자·마감일이 읽기 쉬운 구성을 우선한다.

위젯을 추가한다고 데이터 접근 권한이 확대되어서는 안 된다. 목록 조회, 요약 건수, 검색, 상세 화면 모두 기존 권한을 적용한다.

급여·건강검진 상세 결과·기밀 재무자료·BOM 등 민감한 정보는 기본 홈에 노출하지 않는다.

8. 데이터 연동과 상태 처리

기존 API가 있으면 실제 데이터를 연결한다.

아직 구현되지 않은 기능은:
- 예시 데이터를 실제 운영 데이터처럼 표시하지 않는다.
- 개발용 예시는 별도로 분리하고 예시임을 명시한다.
- 운영 화면에는 ‘연동 준비 중’ 등 실제 상태를 표시한다.

위젯별로 로딩·데이터 없음·권한 없음·조회 실패 상태를 구분한다. 한 위젯 조회가 실패해도 다른 위젯은 정상적으로 표시한다. 조회 실패 시 해당 위젯만 다시 시도할 수 있게 한다.

9. 구현 확인 기준

다음 항목을 실제 동작으로 확인해줘.

- 직원 A의 설정 변경이 직원 B에게 영향을 주지 않는다.
- 저장 후 새로고침해도 순서·크기·표시 설정이 유지된다.
- 편집 취소 시 기존 설정이 정확히 복원된다.
- 위젯 추가·제거·재추가·이동·크기 변경이 동작한다.
- 필터를 바꾸면 실제 표시 내용과 건수가 함께 바뀐다.
- 필수 공지는 개인 편집으로 숨길 수 없다.
- 권한 없는 데이터는 API에서도 조회할 수 없다.
- 모바일에서 내용이 잘리거나 조작 버튼이 겹치지 않는다.
- 개별 위젯 오류가 전체 홈 화면을 막지 않는다.
- 항목을 누르면 해당 문서·업무·일정의 상세 화면으로 연결된다.

먼저 기존 구조를 살펴보고 구현 방식을 짧게 설명한 뒤 작업을 진행해줘. 완료 후에는 변경 내용, 확인 결과, 아직 연동되지 않은 항목만 간단히 정리해줘.
