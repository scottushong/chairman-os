현재 개발 중인 사내 그룹웨어에 전자결재 메뉴와 화면을 구현해줘.

먼저 기존 프로젝트의 기술 스택, 로그인·권한 체계, 데이터베이스, API, 디자인 시스템을 확인하고 기존 구조에 맞춰 작업해줘. 이미 구현된 전자결재 기능이 있으면 재사용하거나 보완하고, 개인 홈의 전자결재 위젯과 동일한 데이터를 사용하도록 연결해줘.

1. 설계 방향

다음 레퍼런스의 장점을 회사 업무에 맞게 반영한다.

- 다우오피스: 결재 대기·예정·참조·수신 구분
- 하이웍스: 신청 승인과 이후 처리 단계 구분
- Microsoft Teams Approvals: 받은 요청과 보낸 요청을 쉽게 찾는 구조
- Kissflow: 현재 단계·다음 담당자·처리 기한·결재 이력 표시

특정 제품의 화면을 그대로 복제하지 말고 기존 그룹웨어 디자인에 맞춰 구현한다.

핵심은 직원이 “지금 내가 처리할 문서는 무엇인가”, “내가 올린 문서는 누구에게 있는가”, “승인 후 실제 업무가 완료되었는가”를 쉽게 확인하는 것이다.

2. 전자결재 메뉴

전자결재 진입 시 ‘결재할 문서’를 기본 화면으로 표시한다.

상단 주요 버튼:
- 새 문서 작성

왼쪽 메뉴:

① 결재할 문서
- 현재 내 차례인 승인·합의 요청
- 대결 권한으로 처리할 문서 포함
- 미처리 건수 표시

② 결재 예정
- 결재선에 포함되어 있으나 아직 내 차례가 아닌 문서
- 현재 단계와 내 예정 역할 표시
- 초기 버전에서는 선결재를 허용하지 않는다.

③ 내가 올린 문서
- 내가 상신한 문서
- 전체 / 진행 중 / 반려 / 승인 완료 / 회수 필터
- 현재 담당자와 단계 표시

④ 임시저장
- 작성 중인 문서
- 이어서 작성·삭제
- 임시 문서는 결재자에게 노출하지 않는다.

⑤ 내 처리 이력
- 내가 승인·합의·반려한 기록
- 내가 처리한 결과와 문서 전체의 최종 상태를 따로 표시
- 내가 중간 승인했다고 문서가 최종 승인 완료로 표시되어서는 안 된다.

⑥ 참조·공유
- 내가 참조자 또는 열람자로 지정된 문서
- 미확인 / 확인 필터
- 열람과 명시적인 확인 처리를 구분
- 승인 버튼은 표시하지 않는다.

⑦ 후속 처리
- 최종 승인 이후 내가 담당하는 구매·지급·행정 처리
- 처리 대기 / 처리 중 / 처리 완료 필터
- 담당자·기한·처리 결과·관련 증빙 표시

개인 설정:
- 자주 쓰는 결재선
- 기간을 지정한 대결자 설정
- 결재 알림 설정

관리자에게만:
- 양식 관리
- 결재선·전결 규칙
- 문서 권한·보관 설정
- 결재·변경 이력 조회

부서 문서함이 필요하면 별도 권한이 있는 사용자에게만 표시한다. 같은 부서라는 이유로 모든 문서를 자동 공개하지 않는다.

3. 목록과 상세 화면

데스크톱에서는 왼쪽 메뉴, 문서 목록, 선택한 문서 상세를 함께 볼 수 있게 구성한다.

문서 목록:
- 제목
- 양식 종류
- 기안자·부서
- 상신일
- 문서 상태
- 현재 결재 담당자 또는 단계
- 처리 기한과 기한 초과 여부
- 제목·기안자 검색
- 상태·양식·기간 필터

별도 기한이 지정된 문서에만 기한 초과를 표시한다.

문서 상세:
- 문서번호
- 제목과 양식
- 기안자·부서·상신일
- 문서 전체 상태
- 현재 결재 단계
- 결재선과 각 단계의 처리자·역할·상태·처리 시각
- 신청 내용과 양식별 입력 항목
- 첨부파일
- 결재 의견과 변경 이력
- 승인 이후 후속 처리 상태
- 관련 문서와 이전 버전 연결

모바일에서는 목록과 상세 화면을 나눠 표시하고 목록으로 돌아갈 수 있게 한다. 문서 내용과 조작 버튼이 잘리거나 겹치지 않도록 한다.

4. 새 문서 작성과 양식

‘새 문서 작성’을 누르면 양식을 선택한다.

초기 양식:
- 구매품의
- 지출결의
- 휴가신청
- 출장신청
- 설비수리 품의
- 일반품의

작성 화면 공통 항목:
- 제목
- 신청 내용
- 기안자·부서 자동 입력
- 결재선
- 합의자·참조자
- 첨부파일
- 필요한 경우 처리 희망일과 후속 담당자
- 임시저장·상신·취소

양식별 항목 예시:
- 구매품의: 품목·수량·거래처·사용 목적·공급가·부가세·합계·납품 희망일·견적서
- 지출결의: 지급처·지급 사유·금액·지급 희망일·증빙·관련 품의
- 휴가신청: 휴가 종류·기간·사용 일수·업무 인수인계
- 출장신청: 기간·방문처·목적·예상 비용
- 설비수리 품의: 설비명·위치·증상·수리 범위·견적·사진

휴가 잔여 일수와 중복 신청 등은 기존 근태 기능이 있으면 연결해 검증한다.

필수 항목과 금액 합계, 첨부 필요 여부, 유효한 결재선은 서버에서도 검증한다.

5. 결재 처리 규칙

초기에는 순차 결재를 기본으로 한다.

- 현재 단계의 지정 결재자만 승인·반려할 수 있다.
- 합의자와 승인자의 역할을 구분한다.
- 참조자는 결재를 진행시킬 수 없다.
- 합의 단계의 완료·반려 규칙은 명시적으로 정의한다.
- 모든 필수 단계가 승인되어야 최종 승인 완료가 된다.
- 중간 승인 후에는 다음 담당자에게 요청을 전달한다.
- 반려 시 사유를 필수 입력한다.
- 승인 의견은 선택 입력하되 기록을 보존한다.
- 상신 이후 신청 내용과 첨부파일을 임의로 덮어쓰지 않는다.

회수:
- 기안자만 요청할 수 있다.
- 최종 승인 전이며 아직 누구도 처리하지 않은 문서만 직접 회수하도록 초기 정책을 적용한다.
- 이미 처리 이력이 있으면 직접 회수를 막고 안내한다.
- 회수하더라도 기존 상신 기록을 삭제하지 않는다.

반려 후 재상신:
- 반려된 원문서와 의견을 보존한다.
- 보완본을 새 버전으로 만들고 원문서와 연결한다.
- 재상신 시 결재선을 다시 검증하고 처음부터 결재를 진행한다.
- 이전 버전의 승인을 자동 승계하지 않는다.

대결:
- 대결자·적용 기간·허용 범위를 명시한다.
- 문서에는 원 결재자와 실제 처리한 대결자를 모두 기록한다.
- 대결 권한은 필요한 문서와 처리 범위에만 적용한다.

상신 시점의 양식 버전과 결재선을 보존한다. 이후 조직도나 기본 결재선이 바뀌었다고 진행 중인 문서를 자동 변경하지 않는다. 퇴사 등으로 처리자를 바꿔야 하면 권한 있는 관리자가 사유를 남기고 변경하도록 한다.

6. 문서 상태와 후속 처리 분리

다음 상태를 서로 구분해 관리한다.

문서 전체:
- 임시저장
- 진행 중
- 반려
- 승인 완료
- 회수

결재 단계:
- 예정
- 대기
- 승인
- 반려
- 취소 또는 종료에 따른 미처리

후속 업무:
- 해당 없음
- 처리 대기
- 처리 중
- 처리 완료

예:
- 구매품의 승인 완료 → 구매 담당자 발주 대기
- 지출결의 승인 완료 → 관리부 지급 대기
- 휴가신청 승인 완료 → 근태 반영 여부 확인

후속 업무는 양식별 설정에 따라 최종 승인 시 생성한다. 동일 문서에 중복 생성되지 않도록 한다.

후속 처리 완료에는 처리자·처리일·결과를 남긴다. 필요한 경우 증빙과 이카운트 전표번호를 연결한다.

후속 업무가 완료되지 않아도 원문서의 승인 완료 상태는 유지한다. 후속 처리 메뉴는 별도 업무관리 기능과 연결할 수 있게 구성한다.

7. 개인 홈 위젯과 연동

개인 홈의 전자결재 위젯과 전자결재 메뉴는 동일한 조회 조건과 권한을 사용한다.

- ‘내 결재 대기’ 숫자를 누르면 결재할 문서로 이동
- ‘내가 올린 문서’에서 해당 문서를 누르면 상세 화면으로 이동
- 승인·반려 후 위젯과 메뉴의 건수가 함께 갱신
- 결재 예정 문서를 결재 대기 건수에 포함하지 않음
- 최종 승인 상태와 후속 업무 상태를 혼합하지 않음

알림은 현재 결재자, 반려받은 기안자, 최종 결과를 확인할 기안자, 후속 담당자에게 필요한 시점에 전달한다. API 재시도 때문에 알림이 중복 발송되지 않도록 한다.

8. 권한·기록·동시 처리

문서 목록, 건수, 검색, 상세, 첨부파일 다운로드, 결재 처리 모두 서버에서 권한을 검증한다.

- 기안자·결재자·합의자·참조자·후속 담당자의 접근 범위를 구분
- 예정 결재자의 사전 열람 범위 명시
- 후속 담당자에게 필요한 본문·첨부·승인 결과만 공개 가능하도록 구성
- 설정 관리자라는 이유로 기밀 문서를 모두 열람하게 하지 않음
- 관련 문서를 연결해도 원문서 접근 권한을 자동 부여하지 않음
- 일반 검색이나 알림에서도 권한 없는 문서 제목·내용이 노출되지 않게 처리

결재 처리에는 사용자·시각·행위·의견·대결 여부·변경 전후 상태를 기록한다.

중복 클릭, 네트워크 재시도, 여러 기기에서의 동시 처리에도 한 단계가 두 번 승인되거나 승인·반려가 동시에 반영되지 않도록 서버에서 처리한다.

상태 변경과 다음 단계 생성은 일관되게 반영하고, 알림 실패 때문에 결재 결과가 잘못 되돌아가지 않도록 한다.

9. 데이터와 오류 처리

기존 API와 실제 데이터를 우선 연결한다.

미구현 기능에 예시 데이터를 넣을 경우 개발용으로 분리하고 명확히 표시한다. 실제 승인·회계 반영·지급이 이루어진 것처럼 보여서는 안 된다.

다음 상태를 구분한다.
- 로딩
- 문서 없음
- 검색 결과 없음
- 권한 없음
- 조회 실패
- 저장·처리 실패

처리 실패 시 입력한 의견과 작성 내용을 유지하고, 실제 서버 상태를 확인한 후 재시도할 수 있게 한다.

10. 확인 기준

다음 동작을 확인해줘.

- 현재 내 차례인 문서만 결재할 문서에 표시된다.
- 중간 승인 후 최종 승인 완료로 바뀌지 않는다.
- 반려 사유 없이 반려할 수 없다.
- 참조자와 예정 결재자는 임의로 승인할 수 없다.
- 회수·재상신·대결이 정의한 정책대로 동작한다.
- 원문서·이전 버전·첨부파일·처리 이력이 보존된다.
- 승인 이후 후속 업무가 한 번만 생성된다.
- 후속 처리 완료가 원문서의 승인 상태를 변경하지 않는다.
- 홈 위젯과 메뉴의 건수가 일치한다.
- 권한 없는 문서와 첨부는 API에서도 접근할 수 없다.
- 중복 요청과 동시 승인·반려를 안전하게 처리한다.
- 모바일에서 작성·조회·결재가 가능하다.
- 기존 그룹웨어 기능에 영향을 주지 않는다.

먼저 기존 구조와 구현 범위를 짧게 정리한 뒤 작업을 진행해줘. 완료 후에는 구현 내용, 검증 결과, 아직 연결되지 않은 기능만 간단히 보고해줘.
