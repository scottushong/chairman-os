기존 원가 엔진 및 월별 손익 계산 기능을 아래 요구사항에 맞게 수정해줘.

이번 작업의 목적은 원료를 한꺼번에 많이 구매한 달에 손익이 과도하게 나빠지고, 구매가 적은 달에는 손익이 과도하게 좋아지는 왜곡을 없애는 것이다.

구매금액을 임의로 몇 개월에 나누거나 평균내는 기능을 만들라는 뜻이 아니다.
원료 구매, 생산 투입, 제품 판매, 현금 지급을 구분하고, 월말 재고를 반영하여 월별 손익을 계산해야 한다.

먼저 저장소의 기존 설계 문서, 코드, 데이터 구조, 테스트를 확인하고 기존 구조에 맞춰 구현해줘.
0061~0067은 관련 설계·기능을 찾는 단서로 사용하되, 번호만 보고 특정 파일이나 기능이 실제로 존재한다고 가정하지 마라.
설명이나 설계안만 작성하고 끝내지 말고, 확인 가능한 범위에서 코드 수정과 테스트까지 진행해줘.

실제 자료가 부족한 부분은 임의의 숫자로 채우지 말고, 필요한 입력과 미확정 상태를 명시해줘.


1. 작업 범위와 유지할 사항

기존 Actual / Current / Market / Forecast 체계는 유지한다.

다만 다음 두 목적을 명확히 분리한다.

- 견적·시장 비교·미래 예측을 위한 원가
- 월별 실적 손익에 반영할 재고평가 및 매출원가

Current나 Market의 최신 값이 변경되었다고 해서 과거 월의 확정 손익까지 바뀌면 안 된다.

기존 영업 견적, 마진 등급, 가격 예외 결재, BOM 비공개 및 원가 열람 권한은 이번 작업에서 임의로 변경하지 않는다.

이번 작업의 우선순위는 회사 전체 월별 손익을 올바르게 계산하는 것이다.
제품별 실제 원가를 계산할 근거가 부족하다는 이유로 회사 전체 손익 계산까지 막지 마라.
반대로 회사 전체 손익을 계산할 수 있다고 해서 제품별 실제 원가도 계산 가능한 것으로 취급하지 마라.

공식 장부에서 사용하는 재고평가방법이 확인되면 그 방법과 연결한다.
기존 방법을 임의로 변경하거나, LOT 연결 여부에 따라 서로 다른 평가방법을 자동 혼용하지 않는다.
확인되지 않은 평가방법은 관리용 잠정 기준으로 표시한다.


2. 회사의 자료와 제약

현재 활용 가능한 자료는 다음과 같다.

- 입고명세서: 원료별 입고수량, 구매단가, 구매금액
- 재고금액명세서: 원료별 재고 및 출고수량
- 제조지시명세서: 제품별 실제 생산수량
- 출하집계표 및 판매자료: 제품별 출하·판매수량과 매출
- 계정별 원장, 급여자료 등: 제조비용과 판매관리비
- 자금흐름표 및 지급자료: 실제 대금 지급과 현금잔액

중요한 제약은 다음과 같다.

- 제조지시명세서는 이름과 달리 생산 완료 후 입력하는 실적자료다.
- 해당 제조지시명세서의 생산수량 단위는 kg이다.
- BOM 접근 권한은 제한되어 있다.
- 현재 자료만으로 원료 LOT와 제품 LOT를 안정적으로 연결하기 어렵다.
- R2 자료는 수량이나 금액에 오류가 있을 수 있다.
- 원료 출고수량은 생산 투입분인지 확인해야 하며, 모든 출고를 생산 투입으로 간주하면 안 된다.

저장소에서 실제로 확인되는 자료 구조와 필드에 맞춰 연결한다.
필드명, 파일 경로, API 조회 가능 여부를 임의로 만들지 않는다.
같은 거래를 R2 자료와 회계자료에서 각각 읽었다고 해서 매입이나 매출을 두 번 반영하지 않는다.


3. 월별 손익의 기본 계산 구조

다음 흐름을 구현한다.

원료 매입
→ 원료 재고
→ 생산 투입
→ 재공품
→ 완제품
→ 판매분 매출원가

원료를 구매했지만 아직 생산에 사용하지 않았다면 원료 재고로 남긴다.
생산 중인 금액은 재공품으로 남긴다.
생산은 끝났지만 아직 판매하지 않은 제품의 원가는 완제품 재고로 남긴다.

정상적인 매입·생산·판매만 있는 경우의 기본 계산식은 다음과 같다.

① 당월 원료 사용액
= 기초 원료 재고금액
+ 당월 원료 순매입금액
- 기말 원료 재고금액

② 당월 제조비용
= 당월 원료 사용액
+ 당월 제조 인건비
+ 당월 제조경비

③ 당월 완성품 제조원가
= 기초 재공품 재고금액
+ 당월 제조비용
- 기말 재공품 재고금액

④ 당월 매출원가
= 기초 완제품 재고금액
+ 당월 완성품 제조원가
- 기말 완제품 재고금액

⑤ 매출총이익
= 당월 매출액 - 당월 매출원가

⑥ 영업이익
= 매출총이익 - 당월 판매관리비

주의사항:

- 위 식은 특수한 재고 변동이 없는 경우의 기본식이다.
- 반품, 폐기, 재고조정, 평가손실, 비생산 출고 등이 있으면 성격별로 분리한다.
- 재고 차이를 전부 생산에 사용한 원료비로 처리하지 않는다.
- 재고조정 손실을 원가에 반영하고 별도 비용으로도 다시 반영하는 중복을 막는다.
- 제조 인건비와 제조경비가 제품 원가에 포함됐다면 손익에서 다시 전액 차감하지 않는다.
- 판매관리비를 미판매 제품 재고에 배분하여 이익을 높이지 않는다.
- 제조원가에 포함할 비용과 당기비용으로 처리할 비용의 구분 및 배부는 기존 승인 기준을 따른다.
- 배부 기준이 없으면 임의로 모든 비용을 재고에 포함하지 말고 잠정 또는 확인 필요로 표시한다.
- 매출 및 매입의 귀속월은 회사의 인식 기준에 따라 정하며, 입금일·지급일로 대체하지 않는다.
- 출하일과 매출 인식일이 다를 수 있으므로 기존 기준을 확인한다.


4. 원료별 원가 계산

원료 LOT 추적이 없어도 계산할 수 있는 구조를 마련한다.

기존에 승인된 평가방법이 있으면 우선 사용한다.
월 가중평균법을 사용하는 경우에는 원료별로 다음과 같이 계산한다.

원료별 월 가중평균단가
= (기초 재고금액 + 당월 순매입금액)
  ÷ (기초 재고수량 + 당월 순매입수량)

원료별 생산 투입원가
= 확인된 생산 투입수량 × 해당 원료의 월 가중평균단가

반품이나 부대원가 등은 기존 취득원가 처리 기준에 맞춰 반영한다.

구현 조건:

- 서로 다른 원료를 전부 합쳐 하나의 평균단가를 만들지 않는다.
- 월 가중평균단가와 입고 시점마다 갱신되는 이동평균단가를 구분한다.
- 월 가중평균단가를 기존 Current 값과 동일한 것으로 취급하지 않는다.
- 생산 투입수량으로 계산한 결과와 재고 증감으로 계산한 결과를 대사한다.
- 두 결과가 다르면 차이를 표시하고 원인을 확인할 수 있게 한다.
- 차이를 없애기 위해 수량, 단가, 금액을 자동으로 맞춰 버리지 않는다.
- 기초재고는 전월 확정 기말재고와 연결한다.
- 최초 적용월의 기초재고는 명시적으로 입력하거나 검증된 자료에서 가져온다.
- 기초재고가 없다는 이유로 자동으로 0을 넣지 않는다.
- 수량이 0이거나 음수인 경우 나눗셈 오류와 비정상 단가 생성을 막는다.
- 평균단가 산출 근거가 없으면 최신 구매가로 조용히 대체하지 않는다.
- 금액과 단가는 기존 기술 스택의 정밀 수치 형식을 사용하고, 반올림 시점과 잔액 처리 기준을 일관되게 적용한다.


5. BOM 없이 재공품·완제품 재고를 반영하는 방법

회사 전체 월별 손익을 위해 다음 입력을 지원한다.

- 월말 재공품 재고평가금액
- 월말 완제품 재고평가금액
- 평가 기준일
- 평가방법 및 포함 원가 범위
- 자료 출처
- 입력자 또는 확인자
- 잠정·확정 상태

이 금액은 권한 있는 담당자가 계산한 값을 수동 입력하거나 기존 자료에서 가져올 수 있게 한다.

회사 전체 손익에서는 승인된 월말 평가금액을 사용할 수 있도록 하고, 반드시 BOM 상세정보를 받아야만 계산되도록 만들지 않는다.

주의사항:

- 완제품 재고금액이 원료비만 포함한 값인지, 제조 인건비·제조경비까지 포함한 값인지 확인한다.
- 기초와 기말 재고의 평가 범위를 일치시킨다.
- 재공품과 완제품을 중복 집계하지 않는다.
- 재공품·완제품 재고금액이 누락되면 자동으로 0을 입력하지 않는다.
- 실제로 재고가 없다고 확인된 0과 자료가 없는 미입력 상태를 구분한다.
- 제품별 배합·원가가 다른데 전체 제조원가를 제품별 kg 비율로 단순 배분하여 실제 원가라고 표시하지 않는다.
- 제품별 원가 연결 근거가 없으면 제품별 실제 마진은 계산 불가 또는 추정으로 표시한다.
- 승인된 배부 기준으로 추정하는 경우에는 기준과 추정 여부를 남긴다.
- 회사 전체 매출원가와 제품별 원가 합계를 연결할 때 배부차이를 숨기지 않는다.


6. 기존 손익 및 원가 엔진과의 연결

먼저 기존 손익 계산이 아래 중 어느 방식인지 확인한다.

A. 당월 매입액을 그대로 비용으로 차감하는 방식
B. 생산 투입원가를 비용으로 차감하는 방식
C. 판매분 매출원가를 이미 계산하는 방식
D. 위 방식이 일부 혼합된 상태

확인한 결과에 따라 필요한 부분만 수정한다.

이미 매출원가나 재고조정이 반영된 손익에 재고 증감을 다시 더하지 않는다.
새 매출원가를 적용하면서 기존 원료 매입비용도 그대로 남겨 두지 않는다.

기존 손익이 매입액과 제조비용을 전부 당월 비용으로 처리하고 있고,
기초·기말 평가 범위가 동일하며 별도 조정이 없는 경우에는 아래 식을 검산에 사용할 수 있다.

재고 반영 손익
= 기존 손익
+ 기말 전체 재고금액
- 기초 전체 재고금액

전체 재고는 원료 + 재공품 + 완제품이다.

단, 이 식을 모든 손익표에 일괄 적용하는 보정 기능으로 구현하지 마라.
기존 원가 반영 방식과 중복 여부를 먼저 확인해야 한다.

Actual / Current / Market / Forecast와의 연결 원칙:

- 기존 Actual의 LOT 추적 기능은 유지한다.
- LOT 추적용 Actual과 월별 장부·관리손익용 평가원가의 차이가 있다면 각각의 기준을 표시한다.
- 기존 0067에서 LOT가 없을 때 출고일 Current를 사용하는 기능이 있다면, 실제로 저장된 당시 값인지 확인한다.
- 그 값이 잠정 대체원가라면 확정 매출원가와 구분한다.
- 최신 Current를 과거 판매분에 소급 적용하지 않는다.
- 잠정 제품별 원가와 월 마감 매출원가 사이에 차이가 있으면 조정 내역을 보여준다.
- Market과 Forecast를 실적 손익 원가로 자동 대체하지 않는다.
- 선매입 효과는 실제 판매원가가 낮아지는 형태로 손익에 반영되므로, 구매이익을 별도로 다시 더하지 않는다.
- 구매성과 분석 화면이나 견적 기준 변경은 이번 작업 범위에서 제외한다.
- 시장가격 하락만으로 재고 장부금액을 자동 변경하지 않는다. 평가손실은 별도 승인된 기준과 절차에 따라 처리한다.


7. 손익과 현금흐름 분리

최소한 다음 금액을 서로 다른 항목으로 관리한다.

- 당월 원료 매입액
- 당월 원료대금 실제 지급액
- 당월 생산 투입원가
- 당월 매출원가

외상으로 매입한 경우 매입 인식월과 지급월을 분리한다.
선급금을 지급했지만 아직 재고로 인식하지 않은 경우에는 지급액을 원료 사용액이나 매출원가로 처리하지 않는다.
전월 매입분을 이번 달 지급해도 이번 달 원가로 다시 반영하지 않는다.

현금 지급은 기존 자금흐름 자료의 실제 지급 내역을 기준으로 집계한다.
손익자료만으로 현금 지급액을 추정하여 확정값처럼 표시하지 않는다.

매입, 지급, 세금계산서, 입고자료 간 금액 차이는 부가세·선급금·외상대금·시점 차이 등으로 설명할 수 있게 한다.

손익 화면에서 다음 상황이 정상적으로 표현되어야 한다.

“이번 달 영업이익은 발생했지만, 원료 선매입 대금 지급으로 현금은 감소했다.”

이익과 현금잔액이 같아지도록 숫자를 임의로 조정하지 않는다.


8. 월별 화면과 마감 관리

기존 보고 화면에 아래 항목을 연결한다.
새로운 대형 대시보드를 별도로 만들기보다 기존 화면을 우선 확장한다.

[손익]
- 매출액
- 매출원가
- 매출총이익
- 판매관리비
- 영업이익

[재고 및 원가 근거]
- 원료 매입액
- 생산 투입원가
- 기초·기말 원료 재고
- 기초·기말 재공품 재고
- 기초·기말 완제품 재고
- 재고조정 및 대사 차이

[자금 참고]
- 원료대금 실제 지급액
- 기존 자금흐름 화면 연결

[자료 상태]
- 입력 중 / 잠정 / 내부 마감 확정
- 누락 자료 및 확인 필요 항목
- 적용한 평가방법
- 계산 버전 및 마감일

화면에서는 매입액과 매출원가가 다른 이유를 확인할 수 있도록 한다.
다만 상세자료가 없는 상태에서 원인을 추정해 단정하지 않는다.

마감 조건:

- 기초재고와 전월 기말재고가 연결되어야 한다.
- 중요한 누락 자료와 미승인 조정이 없어야 한다.
- 회사가 정한 대사 허용오차 기준을 통과해야 한다.
- 자료 부족 상태에서는 내부 마감 확정을 막고 잠정으로 남긴다.

마감 원본과 계산 결과를 보관한다.
원본 데이터를 수정하지 말고 보정값과 보정 사유를 별도 기록한다.
과거 월을 수정하면 이후 월의 기초재고와 손익에 미치는 영향을 추적한다.
이미 확정된 이후 월을 자동으로 덮어쓰지 말고 재마감 대상으로 표시한다.

동일한 원본과 계산 설정으로 다시 계산하면 같은 결과가 나와야 한다.
같은 자료를 다시 업로드하거나 재계산해도 거래와 조정이 중복 생성되지 않아야 한다.

기존 권한 제한은 화면뿐 아니라 API, 내보내기, 로그에도 적용한다.
BOM, 원료별 Actual, LOT 원가 등 제한 정보가 새 기능을 통해 노출되지 않게 한다.


9. 필수 테스트

다음 사례를 자동화 테스트로 작성해줘.
각 테스트의 금액 단위와 가정을 명시해줘.

테스트 1. 원료 선매입 후 3개월 사용

가정:
- 기초 원료 재고 0원
- 첫째 달 원료 매입 9억 원, 이후 두 달 매입 0원
- 매월 원료 3억 원어치를 생산에 사용
- 생산한 제품은 해당 월에 전량 판매
- 재공품과 완제품 기말재고는 모두 0원
- 원료 외 제조비용은 0원
- 매월 매출 5억 원, 판매관리비 1억 원

기대 결과:
- 매월 매출원가 3억 원
- 매월 영업이익 1억 원
- 월말 원료 재고는 순서대로 6억 원, 3억 원, 0원
- 첫 달 매입 9억 원이 전부 첫 달 비용으로 반영되지 않음

별도 지급조건:
- 원료대금 9억 원을 첫째 달에 전액 지급했다면 현금지출은 첫째 달에 9억 원 반영
- 이 지급 때문에 손익 계산 결과가 바뀌지 않음


테스트 2. 생산했지만 일부만 판매

가정:
- 단일 제품이며 기초 재공품·완제품은 0
- 당월 원료 사용액 3,000만 원
- 당월 해당 제품에 배부할 제조 인건비·경비 1,000만 원
- 당월 완성 생산량 10,000kg
- 당월 판매량 6,000kg
- 기말 재공품 0
- 비정상 손실 등 기타 변동 없음

기대 결과:
- 당월 완성품 제조원가 4,000만 원
- 완제품 kg당 원가 4,000원
- 당월 매출원가 2,400만 원
- 기말 완제품 재고금액 1,600만 원
- 제조비 1,000만 원을 손익에서 다시 전액 차감하지 않음


테스트 3. 원료별 월 가중평균

가정:
- 같은 원료의 기초재고 1,000kg, kg당 2,000원
- 당월 매입 1,000kg, kg당 3,000원
- 생산 투입 800kg
- 기타 변동 없음

기대 결과:
- 월 가중평균단가 2,500원
- 생산 투입원가 200만 원
- 기말 재고수량 1,200kg
- 기말 재고금액 300만 원


테스트 4. 전월 완제품 재고 판매

가정:
- 기초 완제품 1,000kg, 재고금액 400만 원
- 당월 생산 없음
- 당월 해당 제품 600kg 판매
- 기타 변동 없음

기대 결과:
- 당월 매출원가 240만 원
- 기말 완제품 400kg, 재고금액 160만 원
- 당월 생산이 없다는 이유로 매출원가가 0원이 되지 않음


테스트 5. 매입월과 지급월이 다른 경우

- 첫째 달 원료를 외상 매입하고 둘째 달 지급
- 매입·재고는 첫째 달에 반영
- 현금지출은 둘째 달에 반영
- 둘째 달 지급액이 원가로 중복 반영되지 않음


테스트 6. 재고자료 누락

- 기초재고 또는 기말 재공품·완제품 평가금액 누락
- 누락을 자동으로 0 처리하지 않음
- 내부 마감 확정 불가
- 원료 사용액까지만 계산 가능한 경우 그 범위와 잠정 상태를 표시


테스트 7. 과거 손익 보호

- 과거 월 마감 후 Current 또는 Market 변경
- 과거 확정 매출원가와 영업이익은 변경되지 않음


테스트 8. 중복 및 비정상 자료

- 동일 자료 재업로드 시 거래 중복 생성 방지
- R2와 회계자료에 같은 매입이 있어도 이중 반영 방지
- 음수 재고 및 투입수량 초과 시 오류 표시
- 임의의 수량·금액 보정 금지
- 재고조정과 비용의 이중 반영 방지


테스트 9. 기존 손익과의 중복 반영 방지

- 이미 재고조정된 손익에 재고 증감을 다시 더하지 않음
- 기존 구매비용을 새 매출원가로 교체할 때 구매비용이 별도로 남지 않음
- 제조비용이 매출원가와 판매관리비에 중복 포함되지 않음


테스트 10. 권한 및 재마감

- 비인가 사용자는 제한된 BOM·원료별 Actual 정보를 조회하거나 내보낼 수 없음
- 과거 월의 승인된 수정이 이후 월에 미치는 영향이 표시됨
- 이후 확정 월을 자동 덮어쓰지 않음


10. 작업 순서와 결과 보고

다음 순서로 진행해줘.

1) 기존 손익·원가·재고·지급 데이터 흐름 확인
2) 현재 구매액이 손익에 반영되는 위치와 중복 위험 확인
3) 기존 구조를 최대한 활용한 최소 변경안 정리
4) 재고평가 및 매출원가 계산 구현
5) 손익·현금흐름 분리와 화면 연결
6) 누락 검증, 마감, 이력, 권한 처리
7) 자동화 테스트 및 기존 기능 회귀 테스트
8) 기존 방식과 새 방식의 결과 차이를 설명하는 검산자료 작성

실제 운영 데이터에 대한 파괴적 변경이나 과거 마감 일괄 덮어쓰기는 하지 마라.
자료 이관이 필요하면 검증 및 되돌리기 가능한 절차를 마련해줘.

작업 완료 후 다음 내용을 보고해줘.

- 확인한 기존 계산 방식과 문제 지점
- 실제 변경한 파일과 기능
- 적용한 계산식과 평가방법
- 기존 네 가지 원가와 월별 손익의 연결 방식
- 추가 입력이 필요한 자료
- 테스트 실행 결과
- 구현하지 못했거나 아직 검증되지 않은 부분

핵심 완료 기준:

원료를 많이 구매했다는 이유만으로 그달 손익이 나빠지지 않고,
실제 판매분의 원가와 당월 비용이 월별 손익에 반영되어야 한다.

동시에 실제 선매입 지급으로 줄어든 현금은 자금흐름에서 그대로 보여야 한다.

자료가 부족한 경우에는 부정확한 확정손익을 만드는 대신,
계산 가능한 범위와 잠정 사유가 명확히 드러나야 한다.
